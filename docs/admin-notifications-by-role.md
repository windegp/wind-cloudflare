# إشعارات الطلبات الجديدة حسب الدور

> **السياسة (قرار المالك 2026-11-28، عُدّل في نفس اليوم ليشمل
> المشاهدة فقط):** إشعار الطلب الجديد يصل **للمالك + الأدمن +
> موظف الطلبات + المشاهدة فقط**. أدوار المنتجات والمحتوى
> **مستبعدون** — لا push ولا تنبيه لحظي داخل الأدمن.

> **المشكلة التي يحلها:** قبل هذا التعديل كانت الإشعارات تصل لأجهزة
> المالك فقط — بالصدفة لا بالسياسة. كل توكن (ويب أو نيتيف) كان
> يُختم بـ `uid` المالك، والإرسال كان يبعت لكل التوكنات بلا أي
> فلترة بالأدوار؛ وفي نفس الوقت متصفح أي موظف غير المالك لم يكن
> يقدر يسجّل توكنه أصلًا (قاعدة `adminTokens` للمالك فقط)، فلا
> موظف طلبات ولا مشاهدة فقط كان يوصله شيء — ولا كان ممكنًا التمييز
> بينهم لو وصل.

## كيف يعمل

1. **الويب** (`src/components/OrderNotifications.js`): عند تسجيل
   التوكن يُخزَّن الـ `uid` والدور الحقيقيان لصاحب الجهاز (من ملف
   الموظف `admins/{uid}` — لا يُؤخذ أي دور من العميل نفسه). الأدوار
   التي لا تستلم الإشعارات لا تسجّل توكنًا أصلًا، ولا تستمع للرسائل
   اللحظية (لا صوت cha-ching ولا توست).
2. **النيتيف** (`POST /api/register-admin-token`): التطبيق لازم يسجّل دخول بحساب
   Firebase Auth (Google) ويرسل `Authorization: Bearer <Firebase ID token>`.
   بلا توكن صالح يرجع `401`، ولو المتصل ليس موظفًا فعّالًا يرجع
   `403` — ولا يُكتب شيء في الحالتين. الـ `uid` والدور يُشتقان من
   التوكن الموثّق ويُخزنان مع التوكن.
3. **الإرسال** (`src/lib/fcmAdmin.js` → `sendNewOrderNotification`):
   عند كل طلب جديد، يُحمَّل الدور **الحالي** لصاحب كل توكن من مستند
   `admins/{uid}` (لا يُعتمد على الدور المخزن وقت التسجيل — قد يكون
   قديمًا بعد تغيير دور الموظف)، ويُرسَل فقط لمن دوره مالك/أدمن/طلبات/
   مشاهدة فقط. أي توكن لا يمكن إسناده لدور مستلم يُتخطى ويُسجَّل عدده في اللوج
   (`skipped`) — لا يُرسَل "للكل" أبدًا عند الشك.
4. الصلاحية نفسها معرّفة في `src/lib/rbac.js` باسم
   `notifications.receive` — مصدر واحد للحقيقة، لا قوائم أدوار
   مكررة في الكود.

## التوكنات القديمة

التوكنات المسجلة قبل هذا التعديل مختومة كلها بـ `uid` المالك، فتُعامل
لحظة الإرسال كتوكنات مالك (تصلها الإشعارات). تُعاد كتابتها بالـ `uid`
الحقيقي تلقائيًا عند إعادة التسجيل: الويب يعيد الحفظ عند كل زيارة
للأدمن والصلاحية ممنوحة، والتطبيق النيتيف يعيد التسجيل عند كل فتح
(بعد تحديثه ليرسل الـ ID token). لا حاجة لحذفها يدويًا.

## ⚠️ ما يجب على المالك تطبيقه بنفسه: قاعدة `adminTokens`

> 🛑 **تحذير: لا تلصق ملفًا كاملًا في الكونسول.** الكونسول بيستبدل
> **كل** القواعد الحيّة بما تلصقه. المطلوب **استبدال كتلة `adminTokens`
> الموجودة فقط** بالكتلة التالية، جوه
> `match /databases/{database}/documents { ... }`، ثم Publish.
> لا تحذف ولا تستبدل أي سطر آخر.

Firebase Console ← مشروع **wind-reviews** ← Firestore Database ← Rules:

```javascript
    // --- New-order notification tokens (per-user, role-filtered) ---
    match /adminTokens/{tokenId} {
      // المالك: كل شيء كما كان.
      allow read, write: if request.auth != null
        && request.auth.uid == "jGb9wBMHZfRIQgR9yfbb3rkvzRw2";

      // الموظف: يسجّل/يحدّث توكن جهازه الخاص فقط — الـ uid في المستند
      // لازم يطابق الـ uid بتاعه (الكتابة من المتصفح عبر setDoc merge).
      allow create: if request.auth != null
        && request.resource.data.uid == request.auth.uid;
      allow update: if request.auth != null
        && resource.data.uid == request.auth.uid
        && request.resource.data.uid == request.auth.uid;

      // الموظف: يحذف توكن جهازه الخاص فقط.
      allow delete: if request.auth != null
        && resource.data.uid == request.auth.uid;
    }
```

**حتى تُطبَّق هذه الكتلة، تسجيل توكنات الويب للموظفين سيستمر في
الفشل بصمت** (يُسجَّل `Failed to save FCM token` في الـ console فقط)
— المالك غير متأثر، والتسجيل النيتيف غير متأثر (السيرفر يتخطى
الـ Rules). الإرسال نفسه (السيرفر) يعمل بلا هذه الكتلة، لكنه لن
يجد توكنات موظفين ليُرسل لها.

## ⚠️ ما يجب تغييره في التطبيق النيتيف (كود خارج هذا الريبو)

التطبيق الحالي يسجّل التوكن **بلا مصادقة**. بعد نشر هذا التعديل،
أي تسجيل بلا `Authorization` سيرجع `401` ولن يُخزَّن التوكن. المطلوب
في التطبيق (قبل النشر أو معه):

1. عند فتح التطبيق، يسجّل المستخدم دخول بحساب Firebase Auth
   (Google — نفس حساب الموظف) إن لم يكن مسجلًا.
2. يأخذ `FirebaseAuth.instance.currentUser.getIdToken()` ويرسله:
   `Authorization: Bearer <idToken>` مع طلب `POST /api/register-admin-token`
   (الـ CORS يسمح الآن بهذا الهيدر).
3. لو الرد `401`، يعيد تسجيل الدخول ثم يعيد المحاولة مرة واحدة.

**أثر النشر قبل تحديث التطبيق:** التوكنات المسجلة أصلًا تبقى وتستلم
الإشعارات كالمعتاد (مختومة مالك). ما يتوقف هو تسجيل التوكنات
**الجديدة أو المتجددة** (FCM يجدّد التوكن دوريًا، والتطبيق يعيد
التسجيل عند كل فتح) — فبعد تجدد توكن جهاز نيتيف، لن يسجَّل الجديد
ولن يصله إشعار حتى يُحدَّث التطبيق. لذلك حدّث التطبيق مع النشر،
لا بعده بفترة طويلة.

## ما الذي لا يفعله هذا الإصدار

- **لا يغيّر أي قاعدة حيّة بنفسه.** الكتلة أعلاه يطبّقها المالك
  يدويًا في الكونسول.
- **لا يغيّر الأدوار** (`rbac.js`: تعريف الأدوار كما هو — أُضيفت
  صلاحية `notifications.receive` فقط، ومُنحت لموظف الطلبات
  والمشاهدة فقط).
- **لا يضيف تعدد الأدوار** (PR مستقل لاحقًا).
- **لا يمس الشيك آوت أو الدفع أو الـ webhook أو الـ Pixel.**
- تسجيل توكن منتجات/محتوى مسموح تقنيًا عبر الـ API لكنه
  يُخزَّن ولا يُرسَل له شيء أبدًا — فلو تغيّر دور الموظف لاحقًا
  لطلبات أو مشاهدة، يبدأ استلام الإشعارات دون إعادة تسجيل.

## ⚠️ التحقق الحي المطلوب بعد النشر (لم يُنفَّذ بعد)

1. طبّق كتلة `adminTokens` أعلاه في الكونسول وPublish.
2. سجّل دخول بحساب موظف طلبات في المتصفح وفعّل التنبيهات —
   تأكد أن مستندًا ظهر في Firestore ← `adminTokens` بحقلَي
   `uid` (الـ UID الحقيقي للموظف) و`role: "orders"`.
3. كرر مع حساب مشاهدة فقط — يجب أن يظهر توكن بدور `viewer`، وأن
   يظهر زر تفعيل التنبيهات.
4. ضع طلبًا تجريبيًا (COD) وتأكد من وصول الـ push لأجهزة
   المالك/الأدمن/الطلبات/المشاهدة فقط.
5. راقب سجلات السيرفر: `order_push_result` يجب أن يظهر `skipped`
   للتوكنات المستبعدة، لا إرسالًا للجميع.
